Set up the `doc/` (documentation) and `issue/` (task lists)
directories in this project, on request only.
Use $ARGUMENTS for any extra instructions.

1. If they already exist, list them and report what's there. Change
   nothing unless $ARGUMENTS asks for it.
2. Otherwise create `doc/README.md` (what the project does and how it
   is built, one markdown file per feature or decision; agents read it
   for context) and `issue/README.md` (one markdown file per issue,
   holding its task list).
3. Adapt to the project's language and existing conventions (e.g. link
   it from the project README if there is a docs section). Don't add
   boilerplate the project doesn't use.
